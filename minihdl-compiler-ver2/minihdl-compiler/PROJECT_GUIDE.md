# MiniHDL Compiler — Project Defense Guide

This document is your preparation reference. It is organised so you can read
top to bottom once, then use it as a lookup table during questioning.

---

## 1. The one-line pitch

> "I built `mhdlc`, a compiler that takes a hardware description language I
> designed — MiniHDL — and takes it through all six classical compiler
> phases: lexing, parsing, semantic analysis, IR generation, optimization,
> and code generation, ending in synthesisable Verilog and a formally
> verified optimizer."

If you only remember one sentence, remember that one. Everything below
expands on it.

---

## 2. Technologies used

| Layer | Technology | Why |
|---|---|---|
| Implementation language | **Python 3.10+** | fast to write, dataclasses give clean AST nodes, no build step |
| Dependencies | **none** (standard library only) | the whole compiler — lexer, parser, optimizer — is hand-written; nothing is generated by a tool like Flex/Bison/ANTLR |
| Output targets | **Verilog-2001**, **C**, **JSON**, **Graphviz DOT** | four independent back ends sharing one IR, proving the IR is truly target-independent |
| Verification | custom exhaustive/random **logic simulator** | no external SAT/BDD library — simulation-based equivalence checking, written from scratch |
| Tooling | **VS Code**, **Graphviz** (`dot`), optionally **Icarus Verilog**, **GCC** | editing/debugging, diagram rendering, running the generated Verilog/C to prove the output is real, working code |
| Testing | a hand-rolled **25-test regression suite** (`tests/test_suite.py`) | no pytest dependency — plain Python assertions, runs anywhere |

**Why no parser generator (Flex/Bison/ANTLR)?** Deliberate choice. Hand-writing
the lexer and parser demonstrates the actual algorithms a Compiler Design
course covers — maximal munch, recursive descent, precedence climbing — rather
than treating them as a black box a tool produces for you. It's also why the
whole project has zero external dependencies: it runs on any machine with
Python, nothing to install.

## 3. Scope of the project

**In scope:**
- A complete combinational hardware description language: modules, typed
  ports (`bit` / `bus[N]`), wires, named constants, bitwise/arithmetic/
  comparison/shift operators, bit indexing and slicing, concatenation,
  the ternary operator, conditional (`when`/`else`) logic, and structural
  module instantiation (hierarchy).
- All six textbook compiler phases, implemented by hand, each with its own
  file and its own well-defined input/output contract.
- A machine-independent optimizer (constant folding, algebraic
  simplification, copy propagation, common subexpression elimination, dead
  code elimination) running to a fixed point, plus one machine-dependent
  pass (technology mapping into a 3-cell NAND/NOR/XNOR-aware library).
- Multiple independent back ends from one IR: Verilog, C, JSON, Graphviz.
- A translation-validation step (`--verify`) that proves the optimizer is
  behaviour-preserving by simulation.
- Full diagnostic infrastructure: precise source spans, caret-underlined
  errors, warnings, hints, and panic-mode error recovery so one run reports
  many problems instead of stopping at the first.

**Out of scope (and why — know this, it shows you understand the boundary):**
- **Sequential logic** (flip-flops, registers, clocks). MiniHDL is
  deliberately purely combinational. Adding sequential elements needs latch/
  flip-flop inference and a clock-domain model — a natural "phase two" of
  this project, not a gap in understanding.
- **A full SAT/BDD-based equivalence checker.** The current checker is
  simulation-based (exhaustive for ≤16 input bits, else 4096 random vectors).
  This is standard practice for small-to-medium circuits and is what the
  project calls *translation validation*; a BDD-based checker would make
  the proof exhaustive for arbitrarily large circuits.
- **Floating-point / signed arithmetic.** All values are unsigned bit
  vectors, which keeps every operator lowering in the IR generator simple
  and is standard for an introductory hardware language.
- **Timing-accurate simulation.** The critical-path metric uses simple unit
  gate delays (`GATE_INFO` in `ir.py`), not real cell-library timing — good
  enough to compare optimization levels, not a sign-off timing tool.

## 4. What it would be used for (real-world framing)

Position this as a miniature, auditable version of what a real hardware
synthesis tool (Yosys, Vivado, Quartus) does internally:

- **Teaching tool**: every phase is small enough to read start-to-finish and
  short enough that a student can trace one expression from source text all
  the way to a gate. Real synthesis tools are too large to read in a
  semester; this one is roughly 3,200 lines total.
- **Rapid circuit prototyping**: write a small combinational block in
  MiniHDL, get a gate count and critical-path estimate immediately, without
  needing a full EDA toolchain installed.
- **Optimizer research sandbox**: because the netlist is tiny and the
  simulator is built in, you can add a new optimization pass and immediately
  measure (a) how many gates it removes and (b) whether `--verify` still
  passes — a complete experiment loop in one file (`optimizer.py`).
- **A base for a bigger project**: the clean IR (`ir.py`) and the six-phase
  boundary make it a natural starting point for extensions (see §7).

## 5. How it meets academic / engineering standards

Map these directly to what a Compiler Design syllabus asks for:

| Standard compiler-course requirement | Where it is in this project |
|---|---|
| Lexical analysis via a DFA-equivalent scanner | `lexer.py` — hand-written scanner with maximal munch |
| Context-free grammar + parser | `parser.py` — the EBNF grammar is in the module docstring and in `README.md` §3 |
| Operator-precedence parsing | `parser.py: parse_binary` — precedence climbing table `PREC` |
| Symbol table with scoping | `symbols.py` — classic chained `Scope` objects (global → module → block) |
| Type checking | `semantic.py: infer/_infer` — width inference *is* the type system here |
| Intermediate representation | `ir.py` — gate netlist, directly analogous to three-address code |
| Machine-independent optimization | `optimizer.py` passes 1–5 (canonicalize, fold/simplify, copy-prop, CSE, DCE) |
| Machine-dependent optimization | `optimizer.py` pass 6 (`_tech_map`) — peephole matching against a cell library |
| Code generation for a target | `codegen.py` — four independent back ends |
| Error detection and recovery | `diagnostics.py` + panic-mode recovery in `parser.py: synchronise` |
| Correctness / verification | `simulator.py: check_equivalence` — translation validation |

Each phase has a single, named responsibility and a typed input/output (AST
in, AST out; tokens in, AST out; and so on), which is the standard way a
compiler course expects phases to be structured — no phase reaches into
another phase's internals.

## 6. Architecture (the picture to draw on a whiteboard)

```
source.hdl
   │ Lexer (lexer.py)            tokens
   ▼
 tokens
   │ Parser (parser.py)          AST
   ▼
  AST
   │ Semantic Analyzer           annotated AST + symbol table
   │ (semantic.py, symbols.py)
   ▼
 annotated AST
   │ IR Generator (irgen.py)     gate netlist
   ▼
 gate netlist ───────────────── (deep copy kept as "reference" for --verify)
   │ Optimizer (optimizer.py)    smaller gate netlist
   ▼
 optimized netlist
   │ Code Generators (codegen.py)
   ▼
 Verilog · C · JSON · Graphviz DOT · self-checking testbench
```

The driver (`driver.py`) is the only file that calls all six phases in
sequence; every other file only knows about its own input and output types.

## 7. Future implementations (have 3–4 ready, don't recite all of them)

1. **Sequential logic**: add a `reg` keyword and `always`-style blocks,
   flip-flop inference, and a clock domain model. The `when`/`else` → MUX
   lowering in `irgen.py` already builds the control-merge logic a
   register's next-state function would reuse.
2. **A real parser-generator front end** (e.g. using PLY/ANTLR) built
   alongside the hand-written one, to directly compare LL/LALR table-driven
   parsing against recursive descent for the same grammar — a natural
   "second front end, same back end" experiment given the IR is already
   decoupled.
3. **SAT/BDD-based equivalence checking** to replace the simulation-based
   checker, making `--verify` exhaustive on circuits with more than 16
   input bits instead of falling back to random sampling.
4. **Area/timing-aware technology mapping** against a real standard-cell
   library (reading a `.lib` file) instead of the hard-coded toy cell table
   in `ir.py: GATE_INFO`.
5. **A web-based playground**: paste MiniHDL source, see the AST, netlist,
   and schematic rendered live in the browser — would reuse every phase as-is
   since they're already pure functions with no file-system dependency
   (see `api.py: compile_text`).
6. **Pipelining/retiming optimizations** once sequential logic exists —
   moving register boundaries across combinational logic to balance
   critical path, a classic "machine-independent" optimization in real
   synthesis tools.

## 8. File-by-file, function-by-function reference

### `mhdlc.py` — entry point
Nine lines. Imports `main` from `minihdl.driver` and calls it with the
process's exit code. Exists so `python mhdlc.py ...` works without needing
`python -m minihdl.driver`.

### `minihdl/diagnostics.py` — error reporting infrastructure
Used by every phase; nothing else is imported by this file (no dependency
cycle).

- **`Color`** — a tiny ANSI colour helper; `.paint()` wraps text in colour
  codes and can be globally disabled (`--no-color`).
- **`Severity`** (enum) — `ERROR`, `WARNING`, `NOTE`.
- **`Span`** — a `(line, col, length)` triple marking where in the source a
  diagnostic applies. `NO_SPAN` is the "no location" sentinel.
- **`Diagnostic`** — one reported problem: severity, which phase raised it,
  the message, the span, and an optional hint string.
- **`CompilerAbort`** — exception type raised to unwind out of a phase once
  that phase has reported errors and cannot usefully continue.
- **`DiagnosticEngine`** — the central collector.
  - `error/warning/note(...)` — convenience wrappers around `emit()`.
  - `has_errors()` / `abort_if_errors(phase)` — used by the driver to decide
    whether to stop after a phase.
  - `render_one(d)` — formats *one* diagnostic rustc-style: severity line,
    `file:line:col`, the actual source line, and a caret (`^^^`) underline
    sized to the span's length.
  - `render_all()` — sorts every diagnostic by position and joins them.
  - `summary()` — the "`N errors, M warnings`" line printed at the end of a
    run.

### `minihdl/tokens.py` — token definitions
- **`T`** (enum) — every token kind: identifiers, numbers, each keyword,
  each operator, each punctuation mark, `EOF`.
- **`KEYWORDS`** — maps the literal keyword spelling (`"module"`, `"wire"`,
  ...) to its `T` value.
- **`OPERATORS`** — an **ordered, longest-first** list of
  `(text, token_kind)` pairs. The order is what makes maximal munch work:
  `"~^"` is tried before `"~"`, so `~^` can never be mis-scanned as `~`
  followed by `^`.
- **`DESCRIBE`** — human-readable names for token kinds, used in parser
  error messages ("expected `';'`, found ...").
- **`Token`** — one scanned token: kind, lexeme (the literal text), span,
  and for numbers, `value` and `width` (for sized literals like `4'b1010`).

### `minihdl/lexer.py` — Phase 1: Lexical Analysis
- **`Lexer`** class — the scanner.
  - `_peek/_advance` — look at or consume the next character, tracking
    line/column as they go.
  - `scan()` — the main loop: skips whitespace, dispatches to
    `_identifier`, `_number`, `_operator`, or comment handling based on the
    current character; reports and **skips** any illegal character so
    scanning continues (this is the error-recovery contract for this
    phase).
  - `_block_comment()` — handles `/* ... */`, and specifically *nested*
    `/* /* ... */ */` comments via a depth counter.
  - `_identifier()` — scans a run of alnum/`_` characters, then looks it up
    in `KEYWORDS` to decide if it's a keyword or a plain identifier.
  - `_number()` — scans a decimal run; if followed by `'` and a base letter
    (`b`/`o`/`d`/`h`), parses a **sized literal** (`8'hFF`), validates the
    width is 1–64 bits, and warns + truncates if the value doesn't fit.
    Otherwise produces a plain unsized decimal literal.
  - `_operator()` — tries every entry of `OPERATORS` in order (longest
    first) against the current position; this is the maximal-munch step.
- **`tokenize(src, diag)`** — module-level convenience wrapper that builds a
  `Lexer` and calls `.scan()`.

### `minihdl/ast_nodes.py` — Abstract Syntax Tree
All nodes are Python `@dataclass`es carrying a `Span`. Expression nodes
(`Expr`) additionally carry `.width` and `.const_value`, filled in later by
semantic analysis — this is the AST's in-place annotation mechanism (no
separate "typed AST" is built).

- Expression nodes: `Number`, `Ident`, `Unary`, `Binary`, `Ternary`,
  `Index`, `SliceExpr`, `Concat`.
- Type/declaration nodes: `TypeNode`, `Port`, `WireDecl`, `LValue`,
  `Assign`, `Instance`, `Block`, `When`, `ConstDecl`, `ModuleDecl`,
  `Program`.
- **`dump_ast(node)`** — recursively renders the tree as an indented
  ASCII-art tree (the `--emit ast` output), via the helper functions
  **`_describe`** (per-node label text) and **`_children`** (per-node list
  of child nodes to recurse into).

### `minihdl/parser.py` — Phase 2: Syntax Analysis
Grammar in EBNF is in the module docstring (also reproduced in README §3).
- **`PREC`** — operator → precedence integer, used by precedence climbing.
  Higher number binds tighter.
- **`Parser`** class
  - `peek/at/advance/match/expect` — low-level token-stream cursor helpers;
    `expect` raises `_PanicError` on mismatch after reporting a diagnostic.
  - `synchronise()` — **panic-mode recovery**: after an error, discards
    tokens until it finds `;`, `}`, or the start of a new top-level
    declaration, so parsing can resume and report further errors in the
    same run.
  - `parse_program/parse_const/parse_module/parse_port/parse_type_opt` —
    top-level and declaration-level grammar rules (recursive descent, one
    function per grammar rule — the standard structure).
  - `parse_block/parse_stmt/parse_wire/parse_assign/parse_lvalue/
    parse_instance/parse_when` — statement-level grammar rules.
  - `parse_expr/parse_ternary/parse_binary/parse_unary/parse_postfix/
    parse_primary` — expression grammar. `parse_binary` is the **precedence
    climbing** core: it loops consuming operators whose precedence is ≥ the
    current minimum, recursing with `precedence + 1` to get left
    associativity.
- **`parse(tokens, diag)`** — module-level convenience wrapper.

### `minihdl/symbols.py` — Symbol Table
- **`Symbol`** — one declared name: its kind (`input`/`output`/`wire`/
  `const`/`module`), bit width, declaring span, constant value (if any),
  and two dataflow flags: `driven` and `read` (used by semantic analysis to
  detect undriven outputs and unused wires).
- **`Scope`** — one lexical scope: a dict of `Symbol`s plus a pointer to its
  `parent` scope (`None` for the global scope).
  - `declare(sym)` — inserts into *this* scope only; returns the previous
    symbol if the name is already taken here (duplicate-declaration check).
  - `lookup_local(name)` — this scope only.
  - `lookup(name)` — walks outward through parents until found or exhausted
    (the standard scoped-lookup algorithm).
  - `dump()` — pretty-prints the whole scope tree (the `--emit symbols`
    output), including the `driven`/`read` flags.

### `minihdl/semantic.py` — Phase 3: Semantic Analysis
- **`SemanticAnalyzer`** class
  - `analyze()` — top-level driver: collect globals, analyze each module,
    then check for recursive instantiation across the whole design.
  - `_collect_globals()` — registers every `const` (after constant-folding
    its value) and every `module` name into the global scope; reports
    duplicate definitions.
  - `const_eval(e)` — evaluates an expression to a Python `int` *at compile
    time* if every operand is a literal or another constant; returns `None`
    otherwise. Used anywhere the language requires a compile-time constant:
    bus widths, bit indices, slice bounds, shift amounts.
  - `_resolve_type(t, where)` — turns a `TypeNode` (`bit` or `bus[expr]`)
    into a concrete integer width, validating it's a positive constant
    ≤ 64.
  - `_analyze_module(m)` — builds the module's scope, declares its ports,
    walks its body, then does the **post-pass dataflow checks**: every
    output must end up `driven`; every wire must be `driven`; a driven but
    never-`read` wire gets a dead-code warning.
  - `_walk_block/_walk_stmt/_walk_assign` — statement-level traversal;
    `_walk_assign` is where "assignment to an input port" and "assignment
    to a constant" are caught.
  - `_lvalue_width(lv, sym)` — computes the bit width of an assignment
    target, validating bit-index and slice bounds are in range and (for
    slices) not reversed.
  - `_check_assign_width(lw, rw, ...)` — the **width-mismatch warning**
    logic: wider-than-target truncates, narrower-than-target zero-extends,
    both reported as warnings (hardware tolerates this; the course point is
    that this *is* the type checker for a bit-vector language).
  - `_walk_instance(st)` — validates a module instantiation: the target
    module must exist, the argument count must match the port count, each
    output-port argument must be an assignable location (`as_lvalue`), and
    each input-port argument's width is checked against the port's
    declared width.
  - `_check_recursion()` — a classic **DFS cycle detection over the
    instantiation graph** (white/grey/black colouring), reporting the
    actual cycle chain if one module ends up instantiating itself, directly
    or indirectly.
  - `infer(e)` / `_infer(e)` — **width inference**, i.e. type checking.
    One case per AST node kind; this is also where "undeclared identifier"
    and "read before driven" are reported, because inferring a name's
    width requires looking it up first.
- **`as_lvalue(e)`** (module-level) — views a plain expression as an
  assignable location (`x`, `x[i]`, or `x[hi:lo]`) so instance-output
  connections can be validated the same way a normal assignment target is.
- **`analyze(program, diag)`** — module-level convenience wrapper.

### `minihdl/ir.py` — the Intermediate Representation
- **`GATE_INFO`** — for every gate type: `(arity, area-in-gate-equivalents,
  unit-delay)`. Drives the area and critical-path statistics.
- **`Gate`** — one netlist entry: `op`, input net list, output net.
  `key()` returns a canonical tuple (sorting inputs for commutative ops)
  used by CSE to recognise `AND(a,b)` and `AND(b,a)` as the same gate.
- **`Netlist`** class — the whole gate-level circuit for one module.
  - `new_net/emit` — allocate a fresh net number / append a gate.
  - `add_input/add_output` — register a named port's net list.
  - `drivers()` — net → the `Gate` that produces it (used by simulation and
    optimization).
  - `fanout()` — net → how many places read it (used by technology mapping
    to only fuse a gate whose single consumer is the `NOT`).
  - `stats()` — gate count, gate-type histogram, net count, area,
    **critical path** (via `critical_path()`, a simple longest-path sweep
    over unit gate delays).
  - `dump()` — the human-readable `--emit ir` / `--emit opt` text listing.
  - `to_dot()` — renders the whole circuit as Graphviz DOT: inputs as
    green "house" shapes, outputs as red house shapes, gates as rounded
    coloured boxes (MUX/XOR get distinct colours), and edges labelled by
    which operand pin they feed. **This is the function behind every
    diagram you've been previewing.**

### `minihdl/irgen.py` — Phase 4: Intermediate Code Generation
This is the "elaboration" or "synthesis" step: AST → gate netlist.
- **`Env`** — the value environment (signal name → list of net numbers,
  one net per bit, LSB first), with a parent chain like `Scope`.
  `snapshot()`/`restore()` exist specifically to support `when`/`else`
  lowering (see below).
- **`IRGen`** class
  - `build(top_name)` — entry point: creates input nets for the top
    module's input ports, lowers its body, then collects output nets.
  - `lower_block/lower_stmt` — statement dispatch, mirroring the AST shape.
  - `lower_assign` → `store(env, lvalue, value)` — writes a computed vector
    into a whole signal, one bit of it, or a slice of it (reused by both
    plain assignment and instance-output connection).
  - `lower_when(st, env, depth)` — the **SSA-style branch merge**: snapshots
    the environment, elaborates the `then` branch, snapshots again, restores
    and elaborates the `else` branch, then for every signal touched in
    either branch emits a `MUX(select, then_value, else_value)` gate —
    exactly a phi-function, which is the standard technique for lowering
    structured control flow into gate-level logic.
  - `lower_instance(st, env, depth)` — **inlining/flattening**: binds the
    instance's actual arguments to the target module's formal ports in a
    fresh `Env` frame, recursively lowers the target's body, then copies
    its output nets back to the caller. `INLINE_DEPTH_LIMIT` guards against
    pathological nesting.
  - `lower(e, env)` — expression lowering, one case per AST node.
    `lower_binary` is where **operator lowering** happens: `<<`/`>>` with a
    constant shift amount become pure rewiring (zero gates — this is why
    `test_shift_and_concat` in the test suite asserts 0 gates for a
    shift-and-concat-only module); `+`/`-` call `add_vec` (ripple-carry
    adder / two's-complement subtractor); `==`/`!=` build an XNOR-tree
    comparator.
  - `add_vec(a, b, invert_b, carry_in, ...)` — the ripple-carry adder
    builder; passing `invert_b=True, carry_in=1` turns the same code into a
    subtractor (standard two's-complement trick: `a - b = a + (~b) + 1`).
- **`generate(program, sema, diag, top)`** — module-level convenience
  wrapper.

### `minihdl/optimizer.py` — Phase 5: Machine-Independent (+ one
Machine-Dependent) Optimization
- **`BASE_OPS`** — maps `AND/OR/XOR` to their complemented form
  `NAND/NOR/XNOR`, used by canonicalization and technology mapping.
- **`PassResult`** — one optimizer pass's before/after gate counts, used to
  build the `--emit stats` report table.
- **`Optimizer`** class
  - `resolve(n)` — union-find-style chase through the `repl` substitution
    map (net → its replacement), with path compression.
  - `run(level, max_iters)` — the overall schedule: canonicalize once, then
    loop {simplify, copy-prop, CSE, DCE} to a fixed point (stops early if
    nothing changed), then at `-O2` run technology mapping + one more DCE.
  - `_canonicalize()` — rewrites every `NAND/NOR/XNOR` into `NOT(AND/OR/
    XOR(...))`, so every later pass only has to reason about a **minimal
    gate basis**.
  - `_inverter_map()` — builds a net → "its logical complement net" map
    from existing `NOT` gates, used by `_simplify` to detect
    complementation (`x & ~x` → 0) without re-deriving it from scratch.
  - `_simplify()` — the **constant folding + algebraic identity** pass: one
    `if` per gate type encoding rules like `AND(x,0)→0`, `OR(x,1)→1`,
    `XOR(x,x)→0`, `NOT(NOT(x))→x`, `MUX(1,a,b)→a`, etc. Matches are recorded
    in `self.repl` rather than mutating gates in place.
  - `_copy_prop()` — removes `BUF` (buffer/pass-through) gates by folding
    them into `repl`.
  - `_cse()` — **common subexpression elimination**: hashes each gate by
    `Gate.key()` (commutativity-aware) and replaces any duplicate's output
    with the first occurrence's output.
  - `_dce()` — **dead code elimination**: backward reachability from the
    module's output nets; any gate not reachable is dropped.
  - `_tech_map()` — the one **machine-dependent** pass: a peephole rule that
    fuses `NOT(AND(a,b))` into one `NAND` gate (and likewise for `OR`/`XOR`)
    whenever the inner gate's only consumer is that `NOT` (checked via
    `fanout()`), because fusing a gate with fan-out > 1 would duplicate
    logic, not save it.
  - `report()` — formats the pass-by-pass before/after/removed table.
- **`optimize(nl, level)`** — module-level convenience wrapper.

### `minihdl/simulator.py` — Verification Support
- **`_eval_gate(op, inputs)`** — the truth-table definition of every gate
  type (`AND`, `OR`, `XOR`, `NAND`, `NOR`, `XNOR`, `NOT`, `BUF`, `MUX`) as
  plain Python bit operations.
- **`simulate(nl, inputs)`** — evaluates the whole netlist for one input
  assignment: seeds the input nets from the `inputs` dict, then does an
  iterative (stack-based, not recursive — avoids Python recursion-depth
  limits on large circuits) evaluation of every net needed to compute the
  outputs, with a fast linear pre-pass for the already-topological common
  case.
- **`input_bit_count(nl)`** / **`_vectors(nl)`** — helpers to enumerate
  every possible input assignment (used by both the truth-table printer and
  the exhaustive branch of equivalence checking).
- **`truth_table(nl, limit_bits)`** — builds the `--emit truth` ASCII
  table; refuses (safely) to enumerate more than `limit_bits` input bits so
  you can't accidentally ask it to print 2⁶⁴ rows.
- **`check_equivalence(a, b, max_exhaustive, samples)`** — the
  **translation-validation** function `--verify` calls: compares two
  netlists (the pre-optimization "reference" copy and the optimized one) on
  every input vector if there are ≤16 input bits, otherwise on 4096
  pseudo-random vectors (fixed seed `0xC0FFEE` for reproducibility), and
  returns the first disagreeing input/expected/actual triple if any.

### `minihdl/codegen.py` — Phase 6: Target Code Generation
- **`VERILOG_OP`** / **`C_OP`** — per-gate-type format-string templates for
  each back end (e.g. `MUX` → `{a} ? {b} : {c}` in both languages).
- **`_port_names(nl)`** / **`_input_names(nl)`** — map a net number back to
  its human-readable HDL name if it's directly a port bit, so generated
  code reads `sum = a ^ b;` instead of `n7 = n3 ^ n4;`.
- **`emit_verilog(nl)`** — structural **Verilog-2001**: port list,
  `wire` declarations for internal nets, one `assign` per gate, with a
  trailing comment naming the gate type and its source line — directly
  synthesisable by Vivado/Quartus/Icarus.
- **`emit_testbench(nl, vectors)`** — a **self-checking** testbench: drives
  every input vector it's given, waits one time unit, and asserts the
  output matches the value our own `simulate()` computed — i.e. the
  "golden" values come from the same simulator that backs `--verify`.
- **`emit_c(nl)`** — a portable **C** function: packs the netlist into two
  structs (`*_in_t`, `*_out_t`) and one `_eval()` function doing the same
  gate computations as the Verilog, letting you compile and run the circuit
  as ordinary C code (this is what was compiled with `gcc` during testing).
- **`emit_json(nl)`** — dumps the netlist as structured data (ports, gates,
  cell-area table, stats) for any external tool to consume.

## 9. Anticipated questions, with model answers

**Q: What makes this a "real" compiler and not just a translator?**
A: It has all the structural properties of a compiler: a formally specified
grammar, a separate semantic-analysis phase enforcing static checks before
any code is generated, an intermediate representation that multiple back
ends target independently, and a machine-independent vs. machine-dependent
optimization split. A translator that just maps text to text (like a
template engine) has none of these phase boundaries.

**Q: Why is the "type system" just bit widths?**
A: In a hardware description language there is no notion of `int` vs
`string` — every signal is a bit vector, so the only thing to check is how
many bits wide it is and whether operations on mismatched widths are legal
(they are, with zero-extension/truncation, exactly like Verilog). Width
inference in `semantic.py: infer()` plays exactly the role a type checker
plays in a general-purpose language compiler.

**Q: How do you know the optimizer doesn't change behaviour?**
A: `--verify` keeps a deep copy of the netlist from immediately after IR
generation (before any optimization pass runs), then after optimization
simulates both netlists on every input combination (or 4096 random samples
if there are more than 16 input bits) and reports the first disagreement,
if any. This is called translation validation — proving each *compilation*
correct rather than proving the compiler correct once and for all.

**Q: Why gate-level IR instead of something like LLVM IR?**
A: The target domain is hardware, where the natural "instruction" is a
logic gate, not an arithmetic/memory instruction. A gate netlist is the
hardware equivalent of three-address code: each `Gate` has exactly the
`result = op operand1, operand2` shape of a three-address-code instruction.

**Q: What happens if I write recursive module instantiation?**
A: Rejected at semantic-analysis time. `_check_recursion()` runs a
white/grey/black depth-first search over the graph of "module X
instantiates module Y" edges; finding a grey (currently-on-the-stack) node
again means a cycle, and the exact chain is reported. Hardware cannot be
recursively elaborated — a physical circuit has no call stack — so this
must be a compile-time error, not a runtime one.

**Q: What's the hardest part of the project to explain?**
A: Lowering `when`/`else`. Software control flow (`if`) skips code; hardware
has no concept of "skipping" — both branches' logic always exists physically
and a multiplexer selects which result to use. `lower_when` in `irgen.py`
implements this by evaluating both branches against two snapshots of the
signal environment and then inserting a `MUX` gate for every signal whose
value differs between the two branches — the same idea as an SSA
phi-function in a software compiler's control-flow merge point.

**Q: Could this handle a bigger circuit, like a CPU?**
A: The combinational parts, yes — module instantiation already inlines
arbitrarily deep hierarchies (bounded by `INLINE_DEPTH_LIMIT = 32`), and the
optimizer and simulator have no circuit-size-specific assumptions baked in.
What's missing is sequential state (registers for a program counter,
memory), which is the first item in the Future Work list.

**Q: Why Python instead of C/C++ for a compiler?**
A: Development speed and readability were the priority for a course
project meant to be read and graded, not a production tool. Python's
`dataclasses` make AST and IR node definitions nearly self-documenting, and
there's no performance requirement here — the largest example compiles in
single-digit milliseconds (see the phase-timing table any run prints).

## 11. Advanced features added in v1.1 (be ready to explain these)

**`minimize.py` — Quine–McCluskey.** For each output bit: list minterms,
repeatedly merge implicants differing in one variable to get prime implicants,
take essential primes, then greedily cover the rest. Limit: 8 input bits (the
truth table is 2^n rows). *Why it matters:* it proves the circuit's logic
function independently of the gate structure; full-adder `cout` reduces to the
3-term majority `a&b | a&cin | b&cin`.

**`timing.py` — static timing analysis.** `arrival(net) = max(arrival of the
gate's inputs) + gate delay`, with a predecessor pointer so the slowest path
can be traced backwards. Slack = critical delay − this output's arrival. No
simulation is needed, which is the defining property of STA.

**`testgen.py` — fault simulation and ATPG.** A stuck-at fault forces one net
to 0 or 1. A vector *detects* the fault if any output differs from the good
circuit. Bit-parallel trick: each net is one Python integer whose bit *v* is
its value under input vector *v*, so one `&`/`|`/`^` evaluates every vector at
once. Test selection is greedy set cover. *Key insight:* faults that no vector
detects are *redundant logic*, so coverage < 100% on an unoptimized netlist
and 100% after `-O2` independently confirms the optimizer.

**`server.py` + `web/index.html` — playground.** `compile_request()` runs the
exact same `api.compile_text` pipeline and returns JSON; the page renders the
netlist as an SVG schematic (columns = logic depth) and re-simulates in
JavaScript when an input is clicked. That JS evaluator was cross-checked
against the Python simulator on every vector tested (zero mismatches).

**Extra viva questions**
- *Why can't a fault in redundant logic be detected?* By definition the
  redundant gate's value never influences any output, so forcing it to 0 or 1
  cannot change an output for any input.
- *Why is QM limited to 8 bits?* It enumerates the full truth table (2^n) and
  the implicant merge is worst-case exponential; production tools use
  Espresso heuristics or BDDs.
- *Is STA the same as simulation?* No. Simulation checks values for specific
  inputs; STA bounds the worst-case delay over all inputs without any vectors.
